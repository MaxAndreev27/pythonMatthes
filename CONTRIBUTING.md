# Contributing Guidelines

Thank you for considering contributing to the **Python Advanced Mastering** study repository! We welcome contributions that improve code quality, fix bugs, refine documentation, or add new Python exercises and implementations.

## How to Contribute

### 1. Reporting Bugs

- Before creating a new issue, check existing issues to avoid duplicates.
- Use the **Bug Report** template when opening an issue.
- Include Python version, environment details, steps to reproduce, and expected vs actual behavior.

### 2. Requesting Features or Improvements

- Open an issue using the **Feature Request** template.
- Describe the feature, motivation, and potential implementation approach.

### 3. Submitting Pull Requests (PRs)

1. Fork the repository and create a new topic branch from `main`:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. Make your changes adhering to project coding standards (PEP 8).
3. Run existing tests or add new unit tests where applicable:
   ```bash
   pytest
   ```
4. Commit your changes with clear, descriptive commit messages.
5. Push to your fork and submit a Pull Request targeting the `main` branch.

## Code Style & Conventions

- Follow **PEP 8** guidelines for Python code style.
- Include clear comments and docstrings (`Google` or `Sphinx` format) where appropriate.
- Ensure type hints are used for function signatures where reasonable.
- Keep notebooks (`.ipynb`) clean and clear of temporary debugging outputs where possible.

## Code of Conduct

Please note that this project is released with a [Contributor Code of Conduct](CODE_OF_CONDUCT.md). By participating in this project, you agree to abide by its terms.
